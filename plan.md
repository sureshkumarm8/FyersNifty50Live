# Implementation Plan — One-Tap Morning + Safe, Measurable AutoTrade

Source analysis: [`AI_AGENT_AUTONOMY_RESEARCH.md`](AI_AGENT_AUTONOMY_RESEARCH.md) (2026-10-23).
Goal: (1) cut the daily routine to **one OTP tap**, (2) make LIVE mode **safe**, and (3) make every
decision **measurable**, so that strategy changes are made on evidence rather than on yesterday's session.

---

## Ground rules (apply to every milestone)

- **One branch per milestone** off `main` (`feat/m1-live-safety`, `feat/m2-new-trading-day`, …), one PR each.
- **No strategy-parameter changes in M1–M6.** Thresholds, targets, stops and windows stay exactly as they are.
  Strategy changes happen only in M7+ and only via a new config version (see M7).
- **AutoTrade stays in PAPER** until M9's promotion criteria are met.
- **Commit messages describe what changed.** Never put a parameter change in a "chore: update expiry" commit.
- **Tests:** run the relevant `ml/*.test.*` suite with `npx --yes tsx <file>`. `ml/multiday.test.mjs` already
  fails one case on HEAD and stops the `npm run model:test` chain, so run later suites individually.
- Each task lists **Done when** acceptance criteria. A task is not done until those criteria are verified.

## M1 — LIVE-mode safety fixes  (`feat/m1-live-safety`)

### M1.1 Lot size from the instrument master (not hardcoded 75)
- Add `constants/lotSize.ts` exporting `NIFTY_LOT_SIZE`, generated by `scripts/generateWeeklyOptions.cjs`
  from `option_security_master.csv` (`lot_size` for `NIFTY-*` rows; currently **65**). Fail the generator
  if NIFTY rows disagree with each other.
- Replace the literals at `components/autotrade/SniperPanel.tsx:48`, `components/autotrade/MomentumPanel.tsx:35`
  and `services/paperTradingService.ts:21` with the import.
- **Done when:** `grep -rn "= 75" components/autotrade services/paperTradingService.ts` returns nothing,
  1 lot = 65 qty in both panels, and a test in `ml/` asserts the constant matches the CSV.

### M1.2 Correct broker symbols
- Add `services/instrumentResolver.ts`: `resolveOptionSymbol({broker, expiry, strike, side})`, which returns
  the exact tradable symbol and security id from the master file. Use the `NSE:` prefix and month code
  for Fyers, and the security id for Paytm.
- Use it in `services/sniperEngine.ts:369` and `components/autotrade/MomentumPanel.tsx:202`.
- If no master row matches, **refuse the order** instead of sending a guessed symbol.
- **Done when:** unit tests cover a weekly expiry, a monthly expiry and an expiry-day case, and an unknown
  strike is rejected before it reaches the server.

### M1.3 No fake success in LIVE
- `server.js:919-925` (Fyers) and `server.js:958-963` (Paytm): when credentials are missing, return
  **HTTP 412 `{ s:'error', code:'NO_CREDENTIALS' }`** instead of a `SIM-*` id.
- `services/orderManager.ts`: treat any `SIM-` id or non-success response as `REJECTED`, and surface it
  in the UI as a red banner.
- **Done when:** with credentials removed, a LIVE order shows REJECTED with the reason, and no log line
  says "simulated fill" for a LIVE request.

### M1.4 Paytm orders use the session token
- `server.js:949-985`: take the token from the request (header `x-jwt-token`, the same as `/api/paytm/quotes`),
  then Redis `paytm:access_token`, and only then `process.env.PAYTM_ACCESS_TOKEN`. Log which source was used
  (never the token itself).
- **Done when:** with no env var set, an order placed after the morning login authenticates using the
  browser token.

### M1.5 Broker order-status sync (PLACED → FILLED)
- `services/orderManager.ts`: add `syncWithBroker()`, called every 3 s while any order is `PLACED`/`PARTIAL`.
  It fetches the broker order book and positions (new server routes `GET /api/fyers/orders` and
  `GET /api/paytm/orders`) and maps statuses to FILLED / PARTIAL / REJECTED / CANCELLED with the average
  fill price.
- When a fill is detected, call `updatePosition` so that the stop, target and hard-stop logic in
  `SniperPanel.tsx:887` sees the position.
- **Mismatch alarm:** if the broker holds a position the app doesn't know about (or the reverse) for more
  than 10 s, raise a blocking alert and disarm auto-entries.
- **Done when:** a test with a mocked broker shows PLACED→FILLED→position→exit at target, and the
  mismatch alarm fires in a mocked orphan-position case.

### M1.6 Exchange-side protective stop
- Right after a LIVE entry fills, place an **SL-M order** at the stop level. Spot stops are converted to
  premium using the live option LTP, not the 0.85-delta estimate. Cancel or modify it on target exit,
  trail or hard-stop exit.
- **Done when:** in LIVE (1 lot, run manually), the broker order book shows the SL-M within 5 s of the fill.
  Closing the browser tab leaves the SL-M in place.

### M1.7 Global kill switch and honest settings
- Add a **"FLATTEN & DISARM"** button to the `UnifiedAutoTrade` header. It cancels open orders, exits all
  positions at market, sets both panels disarmed, and writes `autotrade_killed_<date>` so the panels can't
  re-arm the same day.
- Add `POST /api/kill` on the server, which sets the same flag in Redis. The panels poll it every 5 s, so a
  phone or script can trigger it.
- Either wire `config.liveOrdersEnabled` as a master gate that LIVE requires, or remove it from Settings.
  Pick wiring it in.
- **Done when:** a kill issued from `curl -X POST :5001/api/kill` flattens a paper position within 10 s,
  and LIVE is impossible while `liveOrdersEnabled=false`.

### M1.8 Expiry constants can't go stale silently
- On server start, and in the UI header, compare `CURRENT_EXPIRY_DATE` (generated JS **and** the TS source,
  which currently disagree: `2026-10-19` vs `2026-10-13`) with the next NSE expiry computed from
  `constants/niftyExpiryDates.ts`. On mismatch, show a red banner and block auto-entries.
- **Done when:** setting a past expiry blocks arming, and the banner names the fix (`npm run generate:options`).

## M2 — New Trading Day  (`feat/m2-new-trading-day`)

Replaces the **Reset → Import → AI Capabilities** steps.

### M2.1 Key inventory
Create `services/storageScopes.ts` with two explicit lists:

- **DURABLE** (never auto-cleared): `fyers_creds`, `momentum_settings`, `sniper_lots`, `sniper_sound`,
  `sniper_autostart`, `sniper_auto_paper`, `sniper_auto_live`, `sniper_interval`, `autotrade_mode`,
  `autotrade_tab`, `paytm_symbol_mapping`, `admin_secret`, `user_trading_protocol`.
- **DAY-SCOPED** (cleared on a new IST day): `sniper_day_state`, `sniper_armed`, `sniper_log`,
  `sniper_history`, `sniper_analysis`, `sniper_is_looping`, `sniper_range_*`, `sniper_orderbook_*`,
  `momentum_session`, `momentum_orderbook_*`, `paper_trading_book_v1` (archive first, see M6),
  `opening_pilot_book_v1`, `session_baseline`, `session_data`, `session_start`, `preMarketData`.
- Before finalising, grep for every `localStorage` key once more. Any key not on a list fails a unit test,
  which forces a decision about each new key.

### M2.2 `startNewTradingDay()`
- Store `trading_day` (an IST date). On app load, if `trading_day !== todayIST()` and the time is after
  07:00 IST:
  1. archive day-scoped data (M6 journal, or a JSON download until M6 exists);
  2. clear the day-scoped keys and today's IndexedDB stores (`dbService.clearAll()` already does that part);
  3. leave the PreMkt images and decision alone, because the playbook's `generatedAt` check already
     ignores stale ones;
  4. set `trading_day`.
- Make it idempotent: running it twice in a day does nothing.

### M2.3 Make Reset safe
- Rename the existing button to **"Factory reset (deletes credentials)"**, behind a typed confirmation.
- Add a normal **"Start new day now"** button that calls `startNewTradingDay({force:true})`.
- Import: never overwrite a **newer** token with an older one. Compare token issue times if they are
  available; otherwise ask before replacing.
- **Done when:** after a simulated date change, a reload keeps credentials and AI settings, Sniper and
  Momentum start clean, and no Import is needed.

## M5 — Morning runner  (`feat/m5-morning-runner`)

### M5.1 `scripts/morningRunner.mjs`
Steps, each logged to `~/TradingJournal/<date>/runner.log`:

1. Skip weekends and NSE holidays (add `constants/nseHolidays.ts`).
2. `caffeinate -dimsu -t <seconds until 15:40 IST>` as a child process.
3. Start any of these that are down: `node server.js` (:5001), `vite` (:5173), the sidecar (:4321), Ollama.
   Health-check each with retries.
4. **Pre-flight** (any FAIL means: notify, do not arm, exit non-zero):
   - expiry constants match the next expiry (M1.8);
   - lot size matches the master (M1.1);
   - Redis is reachable;
   - more than 2 GB of free disk;
   - the sidecar is logged in on all targets (`GET :4321/api/status`).
5. **Token:** if `GET /api/token-status` reports no valid token, open the login popup with Playwright
   (persistent profile in `~/.fyers-runner-profile`), then send a notification: *"Enter Paytm OTP"*. Wait up
   to 15 min for `token-status.present`.
6. Open `http://localhost:5173/#premarket?autopull=1`. `startNewTradingDay()` runs on load (M2). Wait for
   `preMarketDecision.generatedAt` to be today (read via a small `GET /api/premarket/status` that the page
   posts to, or by evaluating IndexedDB in Playwright).
7. Send the summary notification: verdict, bias, zones, stale charts, AutoTrade mode.
8. Keep the page open; AutoTrade auto-arms in PAPER (existing behaviour).
9. At 15:35, trigger the EOD export (M6), then close the browser.

### M5.2 Notifications
- `services/notify.mjs`: a macOS notification via `osascript`, plus an optional Telegram bot
  (`TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` in `.env.local`).

### M5.3 launchd
- `scripts/launchd/com.fyers.morningrunner.plist`: weekdays at 08:35, `RunAtLoad=false`, logs under
  `~/TradingJournal/launchd/`.
- `npm run runner:install` and `npm run runner:uninstall` load and unload it.
- **Done when:** for 3 consecutive trading days, the only human action is the OTP, and the 09:05
  notification arrives with a decision dated that day.

## M6 — Disk journal + full scorecard  (`feat/m6-journal`)

### M6.1 Append-only journal
- Add a server route `POST /api/journal/:stream`, which appends JSONL to `~/TradingJournal/<date>/<stream>.jsonl`.
  The streams are `decisions`, `gates`, `orders`, `fills`, `exits`, `premarket`, `vision`, `alerts`.
- `services/journal.ts`: a fire-and-forget client with an IndexedDB retry queue for when the server is down.
- Instrument these:
  - each Sniper and Momentum gate evaluation, sampled once a minute plus on every state change;
  - every order and fill (from M1.5);
  - every pre-market decision and AI review;
  - every kill and mismatch alert.
- Every record carries `configVersion` (M7).

### M6.2 Grade everything
- Extend `services/agentScorecard.ts` with sources `SNIPER`, `MOMENTUM`, `PREMARKET_BIAS`, `VISION_CHART:<slot>`
  and `VISION_SIDECAR`. Use the same +5/15/30 min horizons, Wilson intervals and effective N.
- Add `scripts/gradeDay.mjs <date>`, which replays the journal against that day's `market_history_log`
  and writes `scorecard.json` plus a markdown summary. It must also grade **retroactively** the 8 saved
  pre-market exports and the vision archive. Reuse the logic from the research audit.
- Add a "**vs constant**" baseline: every predictor is compared with always-NEUTRAL and always-majority.
- **Done when:** `node scripts/gradeDay.mjs 2026-10-22` produces a scorecard, and the Momentum and Sniper
  panels show a running track record per config version.

### M6.3 EOD export
- At 15:35 IST (from `lifecycleManager`), write `market_history_log_<date>.csv`, the paper book, the
  decisions and the scorecard into the journal folder. Stop relying on `~/Downloads`.

## M7 — Frozen strategy config + paper forward-test

- Add `config/strategy.v1.json`, which collects every tunable from `services/sniperPlaybook.ts:17-46`,
  `services/momentumEntryGuard.ts:27-68` and `enhancedSignalGenerator` weights. Its values must equal the
  **current** ones exactly.
- The engines read from it. Hash the file to produce `configVersion`.
- Any change means a new file `strategy.v2.json` with a CHANGELOG entry giving the reason and the evidence.
- **Realistic paper fills:** enter and exit paper trades at the **live option LTP ± half the spread** from
  the feed. Fall back to `estimateOptionPremium` only when there is no quote, and mark that trade
  `synthetic:true`; it is excluded from stats. Charges come from the existing `paperTradingService.ts:263`.
- Pre-register the test in `config/forward-test-v1.md`: start date, config hash, metrics and pass criteria
  (from M9). Then **don't touch it for 8 weeks**.
- **Done when:** the paper book shows a `configVersion` on every trade, and no trade uses a synthetic price
  without being flagged.

## M8 — Historical backtest harness

- `scripts/fetchHistory.mjs`: pull Nifty 1-minute candles through the existing Fyers `/api/history` proxy
  in chunks, as many years as the API allows, cached to `~/TradingJournal/history/nifty_1m_<yyyy>.parquet|csv`.
- `ml/backtest/sniperCore.mjs`: replay the **mechanical** Sniper core:
  - zones from prior-day high/low and the opening range;
  - an entry window;
  - spot target/stop/time-stop from `strategy.vN.json`;
  - costs and slippage in points.
- Report: trades, win %, average R, profit factor, max drawdown, and yearly breakdown. Use a strict split:
  **train ≤ 2023, validate 2024, test 2025–26 (touched once)**.
- `ml/backtest/regimeFilter.mjs`: test "no-trade day" filters (gap size, opening-range width, prior-day
  range, VIX if available) on the validation set only.
- **Done when:** one command produces a report for v1 on all three splits, and the result is written into
  the research doc, whatever it shows.

## M9 — Promotion gate + small LIVE

Pre-registered criteria (all required, evaluated by `scripts/promotionCheck.mjs`):

- [ ] ≥ 100 paper trades on one frozen `configVersion`, with real option prices (non-synthetic)
- [ ] profit factor ≥ 1.2 **after** costs, and expectancy with a 95% lower bound > 0
- [ ] max paper drawdown ≤ the agreed rupee budget, and no day worse than the daily cap
- [ ] the M8 out-of-sample test has the same sign
- [ ] M1 completed and verified, including the kill switch and SL-M
- [ ] broker/SEBI retail-algo requirements confirmed with the broker (static IP, algo tagging, session rules)

Live settings:
- 1 lot; daily loss cap; monthly loss cap (auto-disarm for the month);
- SL-M on every entry; kill switch tested weekly;
- manual daily review of the journal for the first 20 live trades;
- scale up only after 100 live trades match paper within tolerance.

## Explicitly out of scope until M9

- Any threshold, target, stop or window retuning
- Option-selling and credit-spread strategies. These are a research track, to be backtested in M8 before
  any implementation.
- An LLM placing or sizing trades. LLMs may only veto or shrink a trade, as `sniperReview.ts` already does.
